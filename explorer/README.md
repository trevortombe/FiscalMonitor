# Fiscal Monitor Explorer

An interactive page for exploring the Fiscal Monitor dataset (`../fiscalmon-clean.csv`): the federal government's monthly revenues, expenses, budgetary balance, financing and balance sheet, as published by the Department of Finance Canada. It runs entirely in the browser, so the finished page needs no server. Upload `fiscal_monitor.html` anywhere, or embed it in WordPress with an iframe.

It follows the Finances of the Nation standards for interactive tools (`../../Finances of the Nation Standards.txt`) and is built the same way as the Government Finances Explorer.

## Files

| File | What it is | Edit it? |
|---|---|---|
| `fiscal_monitor.html` | **The finished tool.** Self-contained (data, code and logo inlined); this is what you upload. | No (regenerated by `build.R`) |
| `../fiscalmon-clean.csv` | The dataset: one row per month × published line | Yes, append each new month |
| `data/items.csv` | Every line: table, label, indentation (`level`), `kind` (item, total or header), `type` (flow, balance or position), `status` (current or discontinued) and `sign` (−1 flips a line's published sign; used for Table 1 expenses) | When Finance Canada adds a line, or to rename one |
| `data/macro.csv` | Canada's annual GDP, population and CPI from the [FON macro database](https://github.com/FONCanada/FONmacro). `build.R` refreshes it from GitHub each time it runs; if it can't connect, it uses this saved copy. | No (refreshed automatically) |
| `data/tables.csv` | The seven tables' titles and the short notes shown under them | Rarely |
| `model.js` | The measures (changes from a year or a month earlier, 12-month totals) and units (2020 dollars, per person, 2020 dollars per person, per cent of GDP) | Only if a formula changes |
| `template.html` | Layout, styling, interface and the Notes text | For design or wording changes |
| `build.R` | Flips Table 1 expense signs, turns the annual macro data into monthly series, packs the dataset and inlines everything into `fiscal_monitor.html`. Settings (tool URL, contact, licence year, base year for real dollars) are at the top. | Settings only |
| `validate.R` | Checks every number the tool can show, in every unit, against `../fiscalmon-clean.csv` and `data/macro.csv`; ends with PASS or FAIL | No |
| `data.js` | The data as JavaScript, written by `build.R`; lets `template.html` run directly | No |
| `FON_logo.png` | Logo | No |

## Monthly update

1. Append the new month to `../fiscalmon-clean.csv` with `../pipeline/fm.py` (see `../CLAUDE.md`; a scheduled task does all four steps and opens a pull request).
2. In R, set the working directory to this folder and run `source("build.R")`. It stops with a message if the CSV has an id that `data/items.csv` doesn't list, a duplicate month × id row, or a value that isn't a number.
3. Run `source("validate.R")`. It should end with `PASS`.
4. Upload the new `fiscal_monitor.html` over the old one.

`build.R` also refreshes the macro data, and reports the last year it covers. When FONmacro adds a new year, the months that were extended with the previous year's growth rates are revised automatically.

The newest month becomes the default automatically: the report-month menu, the headline cards, the date range, the intro text and the citation date all follow the data. Nothing is hard-coded.

If Finance Canada adds a line, add a row for it to `data/items.csv` (build.R will name the id). If a line stops being published, change its `status` to `discontinued` so it moves to the "Discontinued lines" group.

Packages: `dplyr`, `readr`, `jsonlite` (build); plus `V8` (validate). `build.R` needs an internet connection to refresh the macro data, but runs without one.

## Editing the page

Open `template.html` directly in a browser to see changes as you make them (after `build.R` has written `data.js` once). The intro and Notes text are in the HTML. Colours are the CSS variables at the top of the `<style>` block. The default view (lines, table, measure, date range) is the `DEFAULTS` object at the top of the script. Run `build.R` when done.

Set `tool_url` in `build.R` to the page's final address. It appears in chart footers, the citation and CSV downloads.

## What it does

- **Over time:** a line chart of up to 8 lines from any of the seven tables, with end-of-line labels and a hover crosshair. Values can be monthly or fiscal year to date, shown as amounts, changes from a year earlier or from the previous month (absolute or per cent), or 12-month totals.
- **Units** apply to every view: millions of dollars as published, millions of 2020 dollars, dollars per person, 2020 dollars per person, or per cent of GDP.
- **Versus last year:** every line of the chosen table in the report month, as bars, with markers for the same period a year earlier and the per cent change beside each.
- **Monthly statement:** the chosen table as published in the report month, with monthly and year-to-date columns, changes and per cent changes.
- **Headline cards:** the budgetary balance, revenues and program expenses for the fiscal year to date in the report month, against a year earlier.
- Tables behind both charts, with CSV downloads; PNG downloads of both charts; a download of the full dataset.
- **Shareable links:** the whole view is stored in the URL hash.

## Signs and units

- **Table 1 expenses are positive.** Finance Canada publishes program expenses, public debt charges and net actuarial losses in Table 1 as negative numbers. `build.R` flips them (the `sign` column in `data/items.csv`), so they read like Tables 3 and 4 and a rise in spending is a positive change. The budgetary balance keeps its sign. The full-dataset download carries the flipped signs too.
- **Monthly macro series.** GDP, population and CPI are annual. Each becomes a monthly series of straight lines between mid-year points, with the points set so that each calendar year's months average exactly to the annual value. After the last year in the macro data, the series continue that year's growth rate. The page says so whenever an adjusted figure uses those months.
- **How each unit is applied.** An amount is adjusted over the months it covers: the CPI and population are averaged over those months, and GDP is summed over them. So a monthly amount is divided by one month's GDP, and a 12-month total by a year's. Balances (cash, Table 7) are divided by the past 12 months of GDP. Changes are taken after the adjustment. The formulas are set out at the top of `model.js`.

## Differences from the earlier dashboard (`../fiscal-monitor-dashboard.html`)

The earlier dashboard is left in place, unchanged. Every value it holds matches this tool. The differences:

- **Look and build.** It follows the FoN standards: system fonts, FoN colours, hand-built SVG charts with titles, legends, logo and licence inside the chart, and no external requests (the old one loaded Chart.js and a Google font). It is rebuilt from the CSV by `build.R` rather than edited in place.
- **New views and measures.** Versus last year, headline cards, 12-month totals, units (real, per person, share of GDP), PNG and CSV downloads, shareable links and a Notes tab.
- **Month-to-month changes** need two consecutive reports. The old dashboard compared with the previous month *shown*, so across a missing month it compared with an older one.
- **No absolute-value button.** The old "|Absolute values|" button existed to deal with negative Table 1 expenses. Those are now positive in the data, so the button is gone; other signed lines (balances, financing) keep their signs.
- **Units.** The earlier dashboard showed millions of dollars only.
- **April year to date.** Where an April report's year-to-date figure is blank in the CSV, the monthly figure is used, since the two are equal in the first month of the fiscal year.
- **Labels** are in sentence case, keep one name throughout a line's history, and are set in `data/items.csv`. The statement follows each month's published order.
- **Default view.** It opens on 12-month totals of total revenues and total expenses over the past ten years, rather than monthly Table 1 revenues since 2000.
- A dash (`-`) in the CSV is still treated as not reported (n/a), as before.

## Embedding in WordPress

Make a page titled **Fiscal Monitor Explorer** with layout "No Sidebar, Full Width", and put this in one Custom HTML block, with nothing else on the page:

```html
<iframe class="fon-tool" src="https://financesofthenation.ca/fiscal_monitor/"
        title="Fiscal Monitor Explorer"
        style="display:block;width:100%;height:1500px;border:0" scrolling="no"></iframe>
```

That is all it needs. The tool and the WordPress page are on the same site, so the tool integrates itself with the page (embedded mode):

- **Masthead.** It hides its own logo and title and its side padding, so it lines up under the page title. The theme CSS (`Website/fon-tools-theme.css`, already in Appearance → Customize → Additional CSS) styles the page title to match for any iframe with `class="fon-tool"`. Add `data-fon-masthead="show"` to the iframe to keep the tool's own masthead.
- **Height.** It sets the iframe's height to fit its content whenever that changes, so there is no inner scroll bar. The 1500px is only a starting value.
- **Scrolling.** It follows the page's scroll position to keep the sidebar in view on wide screens, to pin a slim bar with the headline numbers at the top of the screen once they scroll away, and to place its pop-up messages and tooltips. "Chart ↑" scrolls the page.
- **Address.** The page's address follows the view, and "Copy link to this view" copies the page's address, so shared links and bookmarks open the WordPress page at that view.

The page and the tool must use the same host name (both `financesofthenation.ca`, no `www.` mismatch). The server caches the tool for about 5 minutes; after uploading, a hard refresh shows the new version.

On narrow screens (iPad portrait, phones, narrow page columns) the tool puts the results first and docks its settings below the chart. On a computer, ‹ › arrows appear at the ends of the view tabs when some are off to the side.

The address shown in chart footers and the citation (`tool_url`, www.financesofthenation.ca/fiscal-monitor) is set at the top of `build.R`. Every view is saved in the URL hash; `#notes` opens the Notes tab.

**On another site** (a different domain), the tool cannot reach the page directly. It then keeps its masthead and falls back to messages: it posts its height (`{fonHeight}`) and scroll requests (`{fonScrollTo}`), and accepts the visible part of the tool from the page (`{fonView: {top, height}}`). Use this longer snippet there:

```html
<iframe id="fon-tool" src="https://financesofthenation.ca/fiscal_monitor/"
        title="Fiscal Monitor Explorer"
        style="display:block;width:100%;height:1500px;border:0;overflow:hidden"
        scrolling="no" loading="lazy"></iframe>
<script>
  (function () {
    var f = document.getElementById("fon-tool"), queued = false;
    function view() {
      queued = false;
      if (!f.contentWindow) return;
      f.contentWindow.postMessage({ fonView: { top: -f.getBoundingClientRect().top, height: window.innerHeight } }, "*");
    }
    function queue() { if (!queued) { queued = true; requestAnimationFrame(view); } }
    window.addEventListener("message", function (e) {
      if (e.source !== f.contentWindow || !e.data) return;
      if (e.data.fonHeight) { f.style.height = Math.ceil(e.data.fonHeight) + 20 + "px"; queue(); }
      if (typeof e.data.fonScrollTo === "number")
        window.scrollTo({ top: f.getBoundingClientRect().top + window.pageYOffset + e.data.fonScrollTo, behavior: "smooth" });
    });
    window.addEventListener("scroll", queue, { passive: true });
    window.addEventListener("resize", queue);
    f.addEventListener("load", queue);
  })();
</script>
```
